# 局域网传输 验证步骤

> 目标：电视上出现一个网址 + 二维码，手机扫码打开上传页后，
> **上传播放列表文件** 或 **发送网址/链接**，电视端实时显示日志并把数据真正写进
> `PlaylistStore` / `SiteStore`；退出页面端口关闭。
>
> 全部结论来自 MuMu 模拟器（`127.0.0.1:16384`）+ 宿主无头 Chrome 实测，
> 不是「编译通过就算完成」。证据截图在 `docs/lan-evidence/`。

---

## 1. 安装与进入（只用遥控器）

```bash
adb connect 127.0.0.1:16384
adb -s 127.0.0.1:16384 install -r TVWebPlayer/dist/TVWebPlayer-0.5.0-debug.apk
adb -s 127.0.0.1:16384 shell monkey -p com.tvweb.player.debug -c android.intent.category.LAUNCHER 1
```

进入首页后：

| 遥控器操作 | 期望结果 | 证据 |
|---|---|---|
| 打开 App | 首页第 3 个磁贴是「局域网传输 · 扫码上传文件 / 发送链接」 | `1-首页新增局域网传输磁贴.png` |
| 方向键 **→** ×2 | 焦点白框落在「局域网传输」 | `2-遥控器焦点落在局域网传输.png` |
| **确认** | 进入二维码页，焦点在「换一个地址」按钮；状态显示 `服务运行中 · 端口 8099` | `3-二维码与网址页.png` |
| **→** | 焦点移到「停止服务并返回」 | — |
| **返回** | 回到首页，端口关闭（见第 4 节） | — |

> 该 Activity 是 `android:exported="false"`，`adb shell am start` 会被拒
> （`Permission Denial: not exported`），必须走首页遥控器导航。
> `run-as` 也绕不过 `assertPackageMatchesCallingUid`，不要试。

## 2. 手机端（真机 / 盒子）

1. 手机与电视连**同一个 WiFi**；
2. 用相机 / 微信扫电视上的二维码，或在手机浏览器直接输入电视上那行网址；
3. 页面上有两块：

| 区块 | 操作 | 电视端结果 |
|---|---|---|
| 上传文件 | 选 M3U / M3U8 / DPL / TXT（可多选），「导入为」选播放列表或站点清单 → **上传并导入** | 绿色结果条；电视日志新增一行 |
| 发送链接 | 一行一个网址，「导入为」选自动 / 站点 / 播放列表 / 立即播放 → **发送到电视** | 同上 |

4. 页面下方「电视上最近收到的」每 5 秒自动刷新，和电视上的日志一致。

**在电视上怎么确认真的进去了**：

- 二维码页右侧「接收记录」实时多一行，顶部「已收到 N 条」+1 → `5-电视端实时接收日志.png`
- 退回首页 → 新站点出现在站点列表
- 进「播放列表」→ 新列表的频道数、中文频道名都正确
- 选「立即播放」→ 电视直接拉起播放器 → `6-发送视频直链拉起播放器.png`

## 3. 模拟器上怎么验证（宿主机当手机）

MuMu 只有 `10.0.2.15`（NAT 地址），宿主机扫不出来，用端口转发代替 WiFi：

```bash
adb connect 127.0.0.1:16384
adb -s 127.0.0.1:16384 forward tcp:18099 tcp:8099
```

然后宿主机访问 `http://127.0.0.1:18099/`。本次实测覆盖的用例：

| 用例 | 命令要点 | 结果 |
|---|---|---|
| 拿到上传页 | `GET /` | 200，8822 字节，含「传到电视」 |
| 传 M3U（含 `#EXTINF` / logo / 分组） | `POST /api/upload` multipart | `「test」2 条` |
| 传 GBK 编码的中文 DPL | 同上，文件名 `中文列表.dpl` | `「中文列表」2 条`，中文频道名无乱码 |
| 一次传 2 个文件 | 同上，2 个 `file` 字段 | 成功 2 个 |
| 传站点清单 | `mode=sites`，含注释行 | 新增 2 个，跳过 2 个（注释 + 空行） |
| 发站点链接 | `POST /api/link` `{mode:"site"}` | 新增 2 个站点 |
| 发播放列表链接 | `{mode:"playlist"}` | 电视自己 GET 该 URL 并导入 2 条 |
| 自动识别 `.m3u8` 频道清单 | `{mode:"auto"}`，内容含 `#EXTINF`、`#EXT-X-` 缺席 | 判为**列表导入**而非直播流 |
| 自动识别普通网页 | `{mode:"auto"}` | 判为站点 |
| 非法行 / 空内容 / 坏 JSON | 同上 | 返回 `ok:false` 与原因，不写脏数据 |
| 404 / OPTIONS | — | 404 / 204 |
| 视频直链 | `{mode:"play"}` | `topResumedActivity=NativePlayerActivity` |

**数据落盘核对**（不是只看返回码）：

```bash
adb shell "run-as com.tvweb.player.debug cat shared_prefs/playlists.xml"
adb shell "run-as com.tvweb.player.debug cat shared_prefs/sites.xml"
```

实测 `playlists.xml` 里能看到 `ch` / `list` / `a` / `b` / `中文列表` 等列表和
「央视新闻」「中文频道」等中文条目；`sites.xml` 里能看到新增的站点，重复 URL 不重复写入。

**浏览器端到端**（真实跑一遍手机页的 JS，不下载 Chromium）：

用一个本机反代把 `/` 换成注入自动脚本的 `lan_upload.html`、`/api/*` 转发到
`127.0.0.1:18099`，再用系统 Chrome `--headless=new --dump-dom` 读回结果：

```
E2E upload=PASS:已处理 1 个文件，成功 1 个 | link=PASS
```

即 Chrome 原生 `FormData` 生成的 multipart 能被服务端正确解析，
页面自己的「发送到电视」按钮也能走通 → `4-手机浏览器上传页与成功结果.png`。

**二维码可扫性**：用 ZXing 官方 `MultiFormatReader` 解码电视截图：

```
image   = 1920x1080
format  = QR_CODE
decoded = http://10.0.2.15:8099/
```

## 4. 生命周期（端口真的关掉）

| 步骤 | `GET /` 结果 |
|---|---|
| 二维码页打开 | `HTTP 200`, 8822 bytes |
| 按 **返回键** 退出页面 | `RemoteDisconnected`（端口已关） |
| 再按 **→** ×2 + **确认** 进入 | `HTTP 200`, 8822 bytes |

服务是页面级的：`LanImportActivity.onCreate()` 起 `ServerSocket`，
`onDestroy()` 关端口，不做常驻 Service、不留无鉴权端口。

## 5. 已知限制（如实说明，不伪装成完成）

1. **「立即播放」只验证到 Activity 被拉起**：本次用的是假 MP4（测试服务器返回文本），
   播放器报 `ERROR_CODE_IO_NETWORK_CONNECTION_FAILED`。真实视频能否播完属于既有播放能力
   （T4）范围，本轮没有重新验证。
2. **二维码是宿主机解码器回读截图**，不是用手机相机真扫；内容已确认正确。
3. **MuMu 二维码里的 `10.0.2.15` 宿主机连不上**，真机/盒子会拿到 `192.168.x.x`；
   模拟器调试必须靠 `adb forward`。
4. **服务无鉴权、纯 HTTP 无 TLS**：同网段任一设备都能写站点/播放列表。
   页面、手机页、README 均已提示不要用在公共 WiFi。
5. 验证过程往模拟器 debug 包写入了测试站点和测试播放列表（站点卡片**长按 → 删除**，
   播放列表分组标题**长按 → 删除**）。
6. `.m3u8` 自动识别靠「前 8 KB 有没有 `#EXTINF`」；服务端不按规范返回文本时可能误判，
   此时在手机页把「导入为」显式选成「导入播放列表」即可。
